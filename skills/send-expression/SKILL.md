# 发送角色表情

`runtime.py` 定义 `send_expression` 工具及周期恢复规则，`scripts/expression_core.py` 定义名称与提示词规则，`scripts/expression_cli.py` 提供脱离宿主的文件图库 CLI。嵌入其他宿主时读取 [宿主接入协议](references/host-api.md)。

## 执行模式

- **宿主插件模式**：由 `runtime.toml` 装载 `runtime.py:create_plugin`，通过 `expression-library` 能力访问当前角色、图库、图片 Provider 和回复草稿。工具定义必须来自本包，不在宿主中重写。
- **独立 CLI 模式**：没有宿主插件系统时运行 `scripts/expression_cli.py`。先用 `inspect` 检查 9:16 基础形象和图库，再用 `prepare --action reuse|generate` 准备图片或图文组件。生成模式读取 `SEND_EXPRESSION_IMAGE_BASE_URL`、`SEND_EXPRESSION_IMAGE_API_KEY`、`SEND_EXPRESSION_IMAGE_MODEL` 和可选超时变量；可能计费且不自动重试。

## 工作流

1. 阅读工具返回的 `expression_catalog` 和 `can_generate` 状态；目录包含名称、情绪、描述和来源。
2. 通常选择 `select` 并描述当前交际意图，让宿主先在本地语义预筛 Top-K；高置信度直接发送，候选相近时才由当前视觉配置查看候选拼图复选。视觉不可用、超时或返回越界序号时，宿主只在本地结果达到最低匹配分数时回退，否则拒绝发送。
3. 用户明确指定已有素材名称、或周期任务需要确定性恢复时使用 `reuse`。复用时必须逐字使用目录中的名称。
4. 只有没有合适素材且 `can_generate=true` 时选择 `generate`；不要为了细微措辞差别重复生成。否则放弃表情，正常使用文字回复。
5. 调用 `send_expression`，一次提交完整的最终回复动作。每轮至多发送一张表情。

## 参数规则

- `action`：混合选择填写 `select`，精确复用填写 `reuse`，生成填写 `generate`。
- `selection_query`：仅在 `select` 时提供，用简短自然语言描述为什么此刻要发表情、希望表达的强度和交际意图；不要放入无关聊天原文或用户隐私。
- `name`：仅在 `reuse` 或 `generate` 时提供。使用简短、可长期复用且能直接看出感情的中文名称，优先采用“情绪或交际意图 + 动作”，例如“开心鼓掌”“安慰抱抱”。复用时必须逐字使用现有名称；生成时必须使用新名称。
- `emotion`：简洁描述核心情绪及强度，不写对用户的判断。
- `image_prompt`：仅在生成时提供，描述角色的表情、姿态和氛围；保持原人物身份与主要外观，不加入用户隐私、聊天原文、文字、水印或新角色。
- `caption`：最终可见文字。需要传递事实、回答问题、作出承诺、提出追问或承接具体话题时，必须附一小段自然文字；只有即时情绪本身已表达完整、不需补充语义时才省略。不解释工具、检索或生成过程。

## 使用边界

- 表情是自然表达，不是每轮必须完成的任务。事实型、严肃、高风险回复默认不用。
- 不声称已经复用、生成或发送；只有工具成功才代表该表情进入待发送回复。
- 周期任务不得使用动态 `select`，必须使用可恢复的精确 `reuse` 或带幂等键的 `generate`。
- `send_expression` 失败后本轮不再调用，改用普通文字完成回复。
- 不输出内部表情名称清单、存储路径、模型配置或工具协议。
